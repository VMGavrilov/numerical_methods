# Отчет по домашнему заданию «Структуры данных и способы генерации списков»

## Блок 1. Поиск элемента: list vs set

**Задача 1. Проверка принадлежности (`in`)**

Поиск в `set` выигрывает с нарастающим отрывом: при \(n = 100\) — примерно в 40 раз, при \(n = 10^3\) — в сотни раз, а при \(n = 10^4\) время проверки в `list` достигает ~125 мкс против ~0,03 мкс у `set` (ускорение свыше 4000×). Причина — асимптотика: `list` проверяет элементы последовательно за \(O(n)\), а `set` использует хеш-таблицу и находит элемент за \(O(1)\). Именно поэтому время у `set` практически не зависит от размера коллекции, а у `list` растёт линейно. Целевой элемент (`-1`) заведомо отсутствует в коллекциях — это худший случай для `list`, что делает сравнение честным.

На графике в логарифмических осях это видно наглядно: линия `list` идёт с постоянным наклоном (линейный рост), а линия `set` остаётся практически горизонтальной.

## Блок 2. Создание списка квадратов: три способа

**Задача 2. Сравнение времени и памяти**

| Способ | N = 100 000 | N = 1 000 000 | Память |
|---|---|---|---|
| Цикл + `append` | 6,62 мс | 74,43 мс | 3,82 / 38,58 МБ |
| List comprehension | 5,33 мс | 63,04 мс | 3,82 / 38,58 МБ |
| Map + lambda | 9,83 мс | 106,92 мс | 3,82 / 38,58 МБ |

**По времени.** List comprehension быстрее цикла с `append` примерно на 15–20%: comprehension выполняет весь код в оптимизированном байткоде цикла `FOR_ITER`, не тратя время на поиск метода `out.append` и его вызов на каждой итерации. Map + lambda оказался самым медленным — на каждом элементе происходит вызов Python-функции `lambda`, и накладные расходы на этот вызов съедают преимущество встроенного `map`.

**По памяти.** Все три способа дают одинаковый пик — ~3,8 МБ при \(N = 10^5\) и ~38,6 МБ при \(N = 10^6\), что соответствует списку из \(N\) Python-объектов `int` (указатели + сами объекты). Это ожидаемо: все способы строят один и тот же полный список в памяти. Память здесь различается не между способами, а между \(N\): рост строго линейный.

**Выводы.**

1. Все способы создают список одинакового размера — пиковая память совпадает с точностью до байта.
2. List comprehension — лучший выбор по скорости: быстрее цикла и стабильно предсказуем.
3. Map + lambda проигрывает из-за накладных расходов на вызов лямбды; он был бы быстрее с встроенной функцией (`map(str, ...)`, `map(abs, ...)`), но с лямбдой преимущество теряется.
