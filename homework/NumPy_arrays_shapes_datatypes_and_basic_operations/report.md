## Блок 1. ndarray, shape, dtype

**Задача 1. Инвентаризация массива**

Создан массив формы `(3, 4, 5)`. Атрибуты `strides` показывают, сколько байт нужно пропустить в памяти, чтобы перейти к следующему элементу по каждому измерению. Для типа `int64` (8 байт) шаги равны `(160, 40, 8)`. Параметр `size = 60`, так как это общее количество элементов (произведение размеров 3 * 4 * 5).

**Задача 2. int vs float — тихая ловушка**

Операция `a / 2` создает новый массив типа `float64`, не изменяя исходный `a`. При прибавлении 127 к массиву типа `int8` происходит переполнение: значения выходят за пределы диапазона `[-128, 127]`, и происходит циклический сдвиг (например, 128 становится -128). NumPy не падает с ошибкой, так как по умолчанию не проверяет переполнение целых чисел (для оптимизации).

**Задача 3. float32 vs float64 — реальная точность**

При вычислении `float(np.float32(0.1)) - 0.1` ошибка составила ~1.49e-09. Ошибка для `float64` оказалась настолько мала, что округлилась до нуля на уровне стандартного `float` в Python. `float32` допустим в задачах, где не требуется высокая точность (графика, машинное обучение, хранение больших массивов). `float64` необходим в численных методах (решение СЛАУ, интегрирование), где ошибки могут накапливаться.

**Задача 4. Явный dtype при создании**

Использование явного типа позволяет контролировать память. `float32` занимает в 2 раза меньше памяти, чем `float64` (на массиве 1000x1000 экономия составляет 4 000 000 байт). Компромисс: `float32` экономит память и ускоряет вычисления, но теряет точность (7 значащих цифр против 15).

## Блок 2. reshape, ravel, flatten, .T, newaxis

**Задача 5. Цепочка reshape**

При изменении формы через `reshape` данные не теряются (проверено через `ravel`). `reshape` обычно не копирует данные, возвращая `view`, если новый порядок совместим с текущим расположением элементов в памяти (C-порядок). Копия создается только при несовместимом порядке (например, `order='F'`).

**Задача 6. flatten vs ravel**

`flatten()` всегда возвращает копию (изменение `f[0]` не затронуло `M`). `ravel()` возвращает `view`, если это возможно (изменение `r[1]` изменило `M`). `ravel` используют для экономии памяти, а `flatten` — когда нужна независимая копия, чтобы случайно не испортить исходный массив.

**Задача 7. newaxis, squeeze, транспонирование**

`v[:, None]` создает столбец `(5, 1)`, `v[None, :]` — строку `(1, 5)`. `squeeze` убирает оси длины 1. Операция `v[:, None] + v[None, :]` через broadcasting создает матрицу `(5, 5)`, которая является таблицей сумм (аналог таблицы умножения).

**Задача 8. Транспонирование без копии**

`A.T` возвращает `view`, а не копию. Это происходит потому, что при транспонировании меняются только `strides` (шаги по осям), а сами данные в памяти остаются на месте. Поэтому изменение элемента в `B` приводит к изменению `A`.

## Блок 3. Операции, агрегации, axis

**Задача 9. Поэлементно vs матричное**

`A * B` — поэлементное умножение (требует совпадения форм). `A @ B` — матричное умножение (свертка по внутренним осям). Для диагональных матриц `D * D` и `D @ D` дают одинаковый результат.

**Задача 10. axis=0 vs axis=1**

`axis=0` сворачивает строки (результат — по столбцам), `axis=1` сворачивает столбцы (результат — по строкам). Например, `sum(axis=0)` возвращает сумму элементов каждого столбца.

**Задача 11. keepdims и broadcasting**

`keepdims=True` сохраняет размерность оси, по которой было выполнено агрегирование (превращает форму `(3,)` в `(1, 3)`). Это необходимо для корректного broadcasting при вычитании среднего из матрицы `(5, 3)`. Без `keepdims` при нормировке по строкам (axis=1) возникла бы ошибка размерностей.

## Блок 4. Индексация, выборки, broadcasting

**Задача 12. Срез — view, не копия**

Срез `a[2:5]` возвращает `view`. Изменение `b[0]` меняет исходный массив `a`. Использование `.copy()` создает независимую копию. В численных методах это критично: случайное изменение среза может испортить исходный эксперимент. `view` полезен для экономии памяти, но опасен при записи.

**Задача 13. Булева маска и fancy indexing**

`a[a > 0]` возвращает значения больше нуля. Объединение масок требует скобок: `(a > 0) & (a < 1)`. Выражение `a[a > 0] & (a < 1)` вызовет ошибку, так как `a[a > 0]` — это уже числа, а не маска.

**Задача 14. Broadcasting в реальной задаче**

Нормировка столбцов выполнена в одну строку без циклов: `(X - X.mean(axis=0)) / X.std(axis=0)`. Матрица попарных расстояний вычислена через broadcasting `Xn[:, None, :] - Xn[None, :, :]`. Получена симметричная матрица `D` размера `(100, 100)` с нулями на диагонали.

**Задача 15. Полный кейс**

Сгенерированы данные 30 дней × 4 датчика. Выброс `raw[7, 2] = 100` успешно найден с помощью маски `> 3 * std`. Заменен на среднее по столбцу через `np.where` и `np.nanmean`. Проведены операции транспонирования (`.T`) и сплющивания (`ravel`/`reshape`), а также нормировка данных.
